# AGENTS.md

**omni-team** — development home of a stack-agnostic AI review team. The distributable framework is the [`.omni-team/`](.omni-team/) folder: consumers copy it into their project and it works immediately. See [README.md](README.md) and [.omni-team/README.md](.omni-team/README.md).

This file is for agents **working on the framework itself**. (Agents *using* the team in a project read [.omni-team/AGENTS.md](.omni-team/AGENTS.md).)

## Critical rules (must read)

Full list: [.omni-team/docs/critical-rules.md](.omni-team/docs/critical-rules.md). Top invariants:

1. **Roles stay stack-agnostic.** [`.omni-team/team/*.md`](.omni-team/team/) hold role + process only — no framework or language names in rules. Project facts are read at run time from `.omni-team/project/`; stack patterns live in signal definitions.
2. **Routing is data, not code.** Signals and rules live in [`.omni-team/defaults.yaml`](.omni-team/defaults.yaml) (overridable in the profile). [`lib/routing.py`](.omni-team/lib/routing.py) only evaluates.
3. **Nothing commits, pushes or merges** — not the orchestrator, not a role, not a skill. The human gate is load-bearing.
4. **`install.py` stays stdlib-only** and only touches files carrying its `generated by omni-team` marker.
5. **Verdicts come only from the last `VERDICT:` line.**
