# Critical rules

Rules for **changing the framework** that must never be silently relaxed. When in doubt, ask the user rather than work around one.

1. **Roles stay stack-agnostic.** `team/*.md`, `_protocol.md` and `skills/` describe role and process only. No framework, language, library or product names in rules ("FastAPI router", "Prisma", "next-intl"); use generic terms ("entry point", "migration tool", "UI string catalogue"). Cross-stack examples in parentheses are fine. Project facts belong in `project/`, stack patterns in signal definitions. See [architecture.md](architecture.md).

2. **Routing is data, not code.** Every pattern and rule lives in `defaults.yaml` / `project/profile.yaml`. `lib/routing.py` evaluates predicates; it never embeds a path, regex, stack or rule name. See [routing.md](routing.md).

3. **Fail loudly.** Invalid YAML, unknown predicates, undefined signals, bad regexes, malformed role frontmatter, unknown roles and unknown engines exit non-zero naming the file and key. No silent defaults that mask configuration errors.

4. **Verdicts come only from the `VERDICT:` line.** `lib/runner.py` parses the last `VERDICT:` line against the token list in `_protocol.md`; anything else is `UNKNOWN` and halts. Never infer a verdict from prose. Token list changes must update `_protocol.md`, `runner.py` and its tests together.

5. **Never commit, push, merge or tag** from any script, role or skill. The human gate is the product.

6. **Stages run serially; only gates of one stage may run together.** Later stages read earlier reports from the artifacts folder. A gate may share a stage only with gates whose reports it does not need. Gate 0 (project checks) always precedes the first AI gate, and an approval is void once the change since it would re-route that gate.

7. **Retry budget is numeric.** Default 3 `REQUEST_CHANGES` and 3 `BLOCK` per gate, then halt and log to `_escapes.md`. No "one more try".

8. **`install.py` stays stdlib-only and only touches its own output.** It may write/delete only files carrying the `generated by omni-team` marker and the delimited pointer block; anything else requires `--force`. Copy-and-run must keep working on a bare Python 3.8+.

9. **Reviewer roles are read-only.** Only `access: run` roles may execute the app, and only write under the artifacts folder. Adapters must preserve this (Claude tool lists, Codex sandbox modes, engine `cmd` vs `cmd_run`).

10. **Public contract changes are breaking.** Role names, rule ids, verdict tokens, conventions section headings, profile keys and predicate names are referenced by host projects. Renames need a migration note in [maintaining.md](maintaining.md) and updates to examples and docs in the same change.

11. **No secrets in checked-in files.** Profiles, conventions, examples and reports are world-readable. API keys flow through the environment only.

12. **Quality limits apply here too** — 500 lines/file, 100 lines/function, 8 parameters, 4 nesting levels. See [code-quality.md](code-quality.md).
